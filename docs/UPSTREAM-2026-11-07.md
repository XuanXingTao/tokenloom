## 实际落地

- `src/tap.js`：只移除已识别的平坦 Node TAP 通过项明细，保留失败、跳过项、未知诊断及汇总；完整输出经过真实 BPE 无收益回退。显式 `--kind tap`，不自动猜测任意日志。
- `src/context.js`：查询词稀有度加权；中文双字切词；24 行块及左右相邻块共同入选；预算包括行号、标记与恢复指令。原文按 SHA-256 存储，读取时核验完整性。写入失败不返回有损包。
- 这只是词法检索与邻接上下文，不是语义向量检索、AST 调用图、全局记忆或自动请求代理。不会因为磁盘存有数据就假定模型知道它。
- 原始表格保真压缩与普通文本默认行为保持兼容；新功能不需要云模型或新增依赖。

## 与 Caveman 的实际差距

[Caveman 固定报告](https://github.com/JuliusBrussee/caveman/blob/9b68f7ed12b05e7efaff18e65c5a3fc2849fd0a4/docs/WRAP-BENCHMARK.md)的 33.2% 是特定 Claude Code 工作负载的 provider 输入节省；98% 左右是查询相关文件选择，依赖原文恢复。会话和文件数据来自不同日期/引擎版本；文档明确其原始 harness 和运行产物未在该 checkout 发布。

TokenLoom 0.1 的 JSON 表格重编码保留所有记录，单纯重编码不能期待同样的 98% 选择收益；而且此前测试的模型、输入规模和宿主不同，不能直接相减。0.2 增加了显式有损查询选择与恢复，补上部分能力缺口，但仍缺少 Caveman 的自动代理、多格式路由和完整恢复调用成本评估。当前没有证据声称整体超过 Caveman。

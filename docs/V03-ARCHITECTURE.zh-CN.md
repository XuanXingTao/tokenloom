# 自动处理、多格式路由与恢复成本：实施方案

状态：设计，尚未实现；依据 TokenLoom 0.2 源码与官方 MCP/插件文档。

实施更新：0.3 已实现 CLI 包装、自动路由、MCP、局部恢复、任务账本和 Codex JSONL 用量收集。下文保留原设计；Git 专用过滤、大输出落盘、自动过期、远程 HTTP 以及完整真实模型对照尚未完成。实际行为以 [使用说明](V03-USAGE.zh-CN.md) 和 [验证结果](V03-RESULTS.zh-CN.md) 为准。

## 范围与接入

优先 Codex 的工具输出层。新增显式 CLI 包装器 `tokenloom run -- <程序> <参数>`，随后提供 MCP 的 read、run、recover 三个工具。只有通过这些入口的内容才能自动压缩；技能引导使用这些工具不等于拦截内置工具。任意命令执行入口必须沿用权限边界、明确工作目录和参数数组，不通过拼接 shell 字符串执行。

ChatGPT 可通过账号支持的插件/MCP 入口使用同一服务，但不能由此承诺控制其内部系统提示、全部历史或隐藏推理。联网服务的身份验证、文件访问范围和部署是独立工作，不能把 Codex 本地 stdio 配置当作 ChatGPT 网页通用安装方式。

## 处理管线

工具执行/文件读取 → 保存原文 → 根据命令、类型和解析结果选择候选处理器 → 包含恢复提示的 BPE 净收益检查 → 返回内容及审计记录。

已有：JSON、扁平 JSON 表格、连续重复日志、Node TAP、显式查询 pack、SHA-256 原文恢复。

新增：路由注册表、CSV 正确解析、JSON Lines 独立记录处理、Git 状态/差异和常见测试输出适配。YAML/HTML 在可靠解析器与测试齐备前原样返回。不同时间戳不能用普通重复行规则合并。代码签名提取须单独使用语法解析器，不通过正则删函数体。

默认只采用已验证的结构变换；查询省略须显式策略授权。压缩失败、无法识别、恢复存储失败或无净收益时返回原文。保留原命令退出码、stderr 来源、超时和取消状态。大输出需落盘与资源限制，不无限缓冲。

## 恢复服务

扩展当前整文件 recover：支持按行区间或结构记录取回，返回来源 hash、范围和是否完整。ID 必须验证，恢复文件必须核验 hash，工作区授权限制不能被存储 ID 绕过。存储设置容量、保留期、清理及并发写入机制。存储不在模型可用范围时明确报错，不让模型猜测缺失内容。

限制每个任务的恢复次数/总字节数；重复恢复和恢复失败均记录。模型请求恢复不是免费步骤，会影响后续模型输入和输出。不能假设模型每次都意识到缺失信息，质量评测必须覆盖这一失败模式。

## 计量

事件字段：taskId、callId、parentCallId、类型、状态、sourceHash、路由、输入/输出本地 BPE、耗时、恢复范围、provider requestId 和 usage（可空）。原文默认只进入本地恢复库，审计日志只写必要元数据。

两套账严格分开：

1. 工具片段账：原文、压缩文本、恢复提示、取回片段的本地 BPE；用于诊断，不能冒充整场消费。
2. 模型调用账：累计完成同一任务的所有请求 usage，含恢复前后、追问和失败重试中实际返回的 usage。工具文本已包含在后续 provider 输入时，不再额外加一次。reasoning 为 output 子项时不重复相加；缓存按 provider 定义记录。

未知 usage 不记为零，标记总量不完整。一次真实运行无法给出未压缩情况下的反事实用量，必须做配对实验。金额需要对应模型/日期/缓存计费桶价格，订阅额度不能由 token 推算。

## 里程碑与验收

1. 路由+run：原退出码保持、失败诊断不丢、无收益原样、超大输出受控；离线回归和真实命令测试。
2. MCP+局部恢复：真实协议客户端测试，读/执行/恢复在新 Codex 会话中工作；验证部分恢复和恢复失败。
3. 任务级账本+模型对照：同模型、同任务、同权限，轮换顺序、多次重复；比较原文组、压缩组、压缩并触发恢复组。所有失败保留。

故意放置首轮遗漏的答案，确认恢复后能答对，并计算净成本；再放置全量统计、跨块约束、格式未识别和短输入等反例。通过确定答案/可执行检查后才评价节省。不能仅以较短输出或关键词命中宣布质量相同。

如果恢复后成本反超原文，按内容类型/任务关闭对应省略策略。适应策略的阈值须用独立验证集，不能在评测集上反复调参后声称泛化收益。
